# Documentation

These guides describe the current system. Each guide owns one topic; source code and Git history own everything else.

## Reading paths

For a first contribution, read:

1. [Product](product.md) for the user experience and the model/code boundary.
2. [Architecture](architecture.md) for processes, data flow, sources of truth, and code ownership.
3. [Development](development.md) for investigation, implementation, testing, evals, and PR workflow.

Then open only the guide that owns the change:

| Change | Guide |
| --- | --- |
| Prompts, model behavior, sessions, tools, images, delivery | [Agent system](agent-system.md) |
| Discord history, retrieval, memory, database, privacy, retention | [Data](data.md) |
| Wallets, transfers, wagers, games, randomness | [Payments and games](payments.md) |
| Local setup, deployment, Console, production debugging | [Operations](operations.md) |
| Production infrastructure shape and its constraints | [Single-node K3s production](architecture/single-node-k3s.md) |
| Accepted environment variables | [Configuration](configuration.md) |

## Documentation rules

Docs say only what code can't: one file per topic, present tense, no history.

- Describe current behavior. Git history and closed PRs preserve how it got here.
- Prefer one complete guide over a README in every source directory.
- Name the canonical owner and the main entry points; do not inventory every file.
- Put credentials and deployment inputs in `.env.example`; put stable product and architecture settings in `src/config/env.ts`.
- Put server-specific prompts, examples, Discord content, and evals in `.discord-ai-agent/` or Postgres, never in tracked docs.
- Update the owning guide when a source of truth, trust boundary, lifecycle, or operator workflow changes. Delete instructions for removed behavior instead of labeling them legacy.
- Keep links relative and run `npm run docs:check` before publication.

[Configuration](configuration.md) is generated by `npm run config:docs`; do not edit it by hand. The root `README.md` is the installation-oriented overview, `AGENTS.md` is the mandatory task router, and `CONTRIBUTING.md` and `SECURITY.md` hold contribution and vulnerability-reporting policy.
